The Datalayer Data Server {{ .Release.Name }} is installed in {{ .Values.namespace }}.

It registers with {{ .Values.dataserver.contentsUrl | default "DATALAYER_CONTENTS_URL (unset!)" }} as
"{{ .Values.dataserver.identity | default "(identity unset!)" }}" and listens on nothing: there is no Service and no
ingress, and none is needed.

Before the first start it needs:

  - Secret {{ .Values.dataserver.apiKeySecret.name }} with key {{ .Values.dataserver.apiKeySecret.key }}:
    the `dataserver` service identity's API key.
  - Secret {{ .Values.dataserver.identitySecret.name }} with tls.crt and tls.key{{ if .Values.dataserver.identitySecret.hasCA }} and ca.crt{{ end }},
    from `datalayer-data-server bootstrap --uid <registration uid>`.

{{ len .Values.dataserver.connectors }} connector(s) are rendered into ConfigMap {{ .Release.Name }}-connectors.

Watch it come up:

  kubectl -n {{ .Values.namespace }} logs deploy/{{ .Release.Name }} -f

Its state — available, draining, unavailable, revoked — is the registration's state in Contents.
