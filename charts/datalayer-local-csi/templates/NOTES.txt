Datalayer Local CSI driver ({{ include "localcsi.driverName" . }}) is installed
in namespace {{ .Values.namespace }}.

Every pod scheduled on a node labelled
{{- range $key, $value := .Values.driver.nodeSelector }} {{ $key }}={{ $value }}{{- end }}
can now carry an ephemeral inline volume:

  volumes:
    - name: local-mount-1
      csi:
        driver: {{ include "localcsi.driverName" . }}
        readOnly: true
        volumeAttributes:
          bridge-uid: <bridge uid>
          sandbox-uid: <sandbox uid>
          mount-mode: ro
          relay-url: wss://{{ .Values.relay.host | default "<relay host>" }}/api/contents/v1/bridges/<bridge uid>
        nodePublishSecretRef:
          name: bridge-<bridge uid>

The Secret must hold the key `mount-token`. The Operator renders all of this
from a Contents attachment with `delivery: local-bridge`.

Check the driver:

  kubectl get csidriver {{ include "localcsi.driverName" . }}
  kubectl -n {{ .Values.namespace }} rollout status daemonset/{{ .Release.Name }}
  kubectl -n {{ .Values.namespace }} logs daemonset/{{ .Release.Name }} -c driver --tail=50
  clouder local-csi status

{{- if not .Values.relay.host }}

relay.host is empty: the driver accepts any wss:// relay host. Set it to the
Contents public host so that a pod cannot point the node at another relay.
{{- end }}
{{- if and .Values.networkPolicy.enabled (not .Values.relay.cidr) (not .Values.relay.namespace) }}

Neither relay.cidr nor relay.namespace is set: the NetworkPolicy restricts
the egress to port {{ .Values.relay.port }} on any destination. Name the relay
to close it further.
{{- end }}
